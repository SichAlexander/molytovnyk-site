Purpose

Home is where the app opens. For a Ukrainian Greek Catholic user — including children (7+) and newcomers to the tradition — it answers "what does today look like, and what should I pray?" in a single scroll, before any deeper navigation. It is both the landing surface (the default NavHost startDestination, MolytovnykRoutes.Home) and the organizational hub: the module also owns the Більше (More) tab, so everything that isn't a primary worship surface — settings, reminders, the streak detail, the saints browser, onboarding — is reached through screens this module ships.

On a fresh install the graph starts at OnboardingWelcome instead; the gate is resolved once by MainActivityV2 from the persisted onboardingShown preference before the NavHost first composes, so there is no Home-then-onboarding flash.

Functionality

HomeScreen composes a vertical stack of independent sections (under sections/), each backed by state the HomeViewModel derives from preferences, the liturgical engine, and the streak/reminders stores:

  • Greeting + top bar — GreetingSection / TopBarSection, with a time-of-day greeting (re-evaluated via GreetingBoundaryTick) and a bell button routing to Reminders plus an avatar routing to Settings → account.
  • Daily / feast card — DailyCardSection (DailyCard) renders the day's feast or saint. A GREAT_SAINT day exposes a "Свято дня" CTA that opens the GreatSaintReveal sheet (tropar + kondak).
  • Prayer-task list with streak credit — TaskSection lists the day's prayer slots; the HomeViewModel computes the routineId from the time window (morning < 11:00 · daily 11:00–19:00 · evening from 19:00) and never re-offers a completed slot. Tapping a task opens the @Modal PrayerSessionScreen; completing it credits the streak (surfaced in StreakDetailScreen).
  • Upcoming-events strip — UpcomingEventsSection shows the next parish/calendar events; CTAs route to the calendar, a specific day, or the dedicated 14-day UpcomingEventsListScreen, with an empty-state "add event" path.
  • Permission / nudge banners — the two reminder banners are mutually exclusive by construction. HomeViewModel exposes a private BannerGates(showPermissionBanner, showReminderNudge) holder whose combine fold sets showReminderNudge = raw && !permissionBanner — the invariant is enforced at the data layer, not by an else if in the screen. The permission banner fires only when a slot is enabled but notifications are denied; the nudge only when no slot is enabled.
  • More hub + sub-surfaces — MoreScreen (MoreViewModel) is the curated Більше landing (grouped Читання / Парафія / Молитовний ритм / Застосунок lists) and the inbound edge to SettingsRoute, RemindersRoute, the Psalter family, ParishPicker, SaintsBrowserScreen, SupportRoute/PrivacyRoute/AboutRoute, the Spiritual Advisor (flag-gated), and onboarding re-run. Capability gates (e.g. createEventEnabled = parishName != null) live in the ViewModels.

Navigation flow

Home is the first of the bottom-nav tabs and the NavHost's default startDestination (MolytovnykRoutes.Home). The user reaches its sub-surfaces two ways: directly from Home (a task opens the @Modal PrayerSession; the bell opens RemindersSettings; the avatar opens Settings anchored to the account band; the streak chip opens StreakDetail; event CTAs open the calendar or UpcomingEvents), or via the Більше tab, which fans out to Settings, Reminders, Psalter, parish tools, Support/Privacy/About, the saints browser, and the Spiritual Advisor. Tab-to-tab moves (e.g. the Community card) use popUpTo(start) + saveState + restoreState + launchSingleTop so back from a tab returns to Home, not a redundant stack entry. Modal routes get full-screen treatment and hide the bottom nav; back from a modal pops to the surface that launched it. On first launch the start destination is OnboardingWelcome instead, and the pager (Welcome → SignIn → Parish → Reminders → [AngelDay, pilot-gated]) flips onboardingShown on exit, landing on Home.
