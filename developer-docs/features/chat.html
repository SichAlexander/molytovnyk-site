Purpose

The Spiritual Advisor is an AI-powered Q&A surface aimed at the same audience as the rest of the app — children (7+) and newcomers to the Ukrainian Greek Catholic tradition — who have a question about prayer or spiritual practice and want a grounded, plain-language answer.

  • Grounded, not free-floating. Answers are anchored to the app's own bundled knowledge base (knowledge_base.json / spiritual_counseling.json) via the keyword-only RagUseCase, which retrieves the top-3 relevant chunks and feeds them to the model as context. The advisor is a retrieval-augmented Q&A over a small curated corpus, not an open-ended chatbot.
  • Default-off and explicitly experimental. The feature ships behind the default-OFF spiritualAdvisorEnabled flag for the pilot, and its label carries a load-bearing "(бета)" suffix (SpiritualAdvisorStrings.SETTINGS_LABEL = "Духовний помічник (бета)") so users know it is experimental.
  • Honest about its limits. The surface never fakes capability: when no key is provisioned or the network is down it shows a clearly-labelled offline keyword answer ("ОФЛАЙН-ВІДПОВІДЬ") rather than pretending an LLM responded, and it degrades to a soft UA error instead of crashing.
The advisor is stateless — there is no saved conversation history persisted across sessions; each question is answered against the freshly-retrieved chunks. The transcript shown is the in-session message list only.

Functionality

The surface is a single send-then-stream chat canvas. ChatScreenContent is pure-render: every pixel is a function of (state, messages) plus the onSend / onRetry / onBack callbacks — no ViewModel, no clock reads, no self-mutating state — which is what makes every state Paparazzi-snapshottable. The ChatViewModel (in :app) produces the state; the nav route collects its StateFlow and renders the feature composable.

Honest latency contract. The legacy chat faked AI latency with a delay(50) word-by-word typing loop on an answer it had already computed. That theatre is gone. The in-flight pane below the transcript now reflects the real send-result via the sealed ChatUiState:

  • Connecting — request sent, no tokens yet (online path only); renders a labelled "З'єднання…" pending row. The composer is disabled.
  • Streaming — real text_delta tokens arriving progressively; partial grows as the SDK stream delivers them, with a static trailing cursor glyph (no faked typing animation layered on top).
  • Done — the complete online answer settled; nothing extra in the pane (the answer already lives in messages) and the composer re-enables.
  • OfflineFallback — the NoKey / Offline keyword answer, emitted instantly (no fake typing), under a visible "ОФЛАЙН-ВІДПОВІДЬ" label so the user knows it is the degraded path.
  • Error — a soft UA error row (never a crash); a "Спробувати знову" retry link appears only when retryable.
sealed interface ChatUiState {
    data object Connecting : ChatUiState
    data class Streaming(val partial: String) : ChatUiState
    data class Done(val full: String) : ChatUiState
    data class OfflineFallback(val text: String) : ChatUiState
    data class Error(val messageUa: String, val retryable: Boolean) : ChatUiState
}

Availability resolution. A companion AdvisorAvailability (the static + connectivity half) is resolved at send-time by AdvisorAvailabilityResolver in :app — which can read BuildConfig.ANTHROPIC_API_KEY and a ConnectivityManager a feature module can't reach:

  • Online — a key is compiled in and a validated network is reachable → real streaming LLM call.
  • NoKey — ANTHROPIC_API_KEY is blank (no key provisioned at build time) → keyword-only RAG fallback.
  • Offline — a key is present but no validated network → keyword-only fallback for the outage; re-resolves to Online on the next send once connectivity returns.
A 401 from a present-but-invalid key is not NoKey — it surfaces as a thrown SDK exception that the ViewModel maps to a typed ChatUiState.Error. NoKey is strictly the "no key was compiled in at all" static branch.

Dependencies

This module is the presentational surface only. It declares buildConfig = false and reads no key and no BuildConfig — the streaming client, the ViewModel, and the Anthropic SDK all live in :app because they need :app-scoped resources (the ANTHROPIC_API_KEY BuildConfig field, KnowledgeBaseRepository's res/raw JSON, ConnectivityManager) that a feature module cannot depend up to.

Navigation flow

The advisor is not a bottom-nav tab. It is reached through the Більше (More) tab, where a row labelled "Духовний помічник (бета)" is rendered only when state.spiritualAdvisorEnabled is ON. Tapping that row fires the onOpenSpiritualAdvisor callback, which calls navController.navigate(MolytovnykRoutes.SpiritualAdvisor) — route value "advisor".

The route constant is annotated @Modal, so KSP places it in the generated MODAL_ROUTES set and MainActivityV2 gives it full-screen treatment with the bottom nav rail hidden — the focused Q&A canvas owns the screen. Back uses popBackStack() via the top-bar "←" affordance, returning to the More tab.

The static navigate edge is always present in the graph (so RouteReachabilityTest never flags the route as an orphan); the spiritualAdvisorEnabled flag only controls whether the More row renders, not whether the edge exists. With the flag OFF (the pilot default) the user simply never sees the row, so the route is unreachable in practice.
