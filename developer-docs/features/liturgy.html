Purpose

Liturgy is the daily Divine Liturgy reader and the highest-traffic surface in the app. For a given date it produces the day's Ordo — the ordered text of the Божественна Літургія св. Івана Золотоустого (and the Liturgy of St Basil on its ~10 days/yr) — deterministically, so the same date and calendar mode always render the same blocks.

The assembly is offline-first and rule-driven: LiturgyAssemblyOrchestrator wraps the :core:database engine (rules + CalendarService + RichContentProvider + LiturgyGenerator), so the reader itself never touches JSON parsing, feast lookup, or template generation. Calendar mode (GREGORIAN default / JULIAN) is read once per assemble() from user prefs (prefs.calendarMode, Wave OT.8), so flipping the Julian toggle takes effect on the next assembly without leaving the screen.

Functionality

  • Five-role rendering contract. The assembled List<LiturgyDisplayBlock> is mapped to UI rendering roles by LiturgyBlockTypeMapper (now in :core:domain commonMain) into one of five roles — Rubric, Said, Sung, PeopleSung, Response — and drawn by LiturgyBlockText() from :core:designsystem, which owns the role colours and typography.
  • Paginated, section-grouped reader. LiturgySectionGrouper flattens the flat block list into LiturgySectionV2 screens. LiturgyViewModelV2 drives the reader state machine: currentIndex, a per-session readSections set (marked as the user advances; not persisted — re-opening starts at section 1), section pips, and the (pilot-gated) completion overlay. Navigation is back / next / swipe via next() / previous(); there is no per-section confirm button.
  • In-place ♪ notation-sheet toggle (Wave C.5). For the core-5 sung parts, ChantRepository.chantForBlock resolves a ScoreChant for the current section (currentChant); when present, the ♪ button shows and showNotes()/hideNotes() crossfade the text body to a ScoreView (notesVisible, reset to false on every section change). Gated OFF for the pilot by LiturgyFeatureFlags.NOTATION_SHEETS_ENABLED (the core-5 content is still owner/clergy-gated, #1247); when off the ♪ button never renders.
  • Liturgy TOC as an in-screen sub-state, not a route. isTocShown with openToc()/closeToc()/jumpTo(index). In single-pane it renders as a full-screen overlay; in the expanded tablet layout it becomes a persistent pane beside the reader (no overlay) — the overlay is gated on state.isTocShown && !layoutMode.hasPersistentToc.
  • Tablet multi-pane layouts (Wave TB.A). liturgyLayoutModeFor(widthDp) maps a measured width to LiturgyLayoutMode — SinglePane (<600dp) → SinglePaneCapped (600–839dp, body capped to the reading measure) → TwoPane (840–999dp, persistent TOC) → ThreePane (≥1000dp, persistent TOC + reader + notation supporting pane). Routes on width class, never orientation. A ReadingStyle toggle (Сувій scroll / Книга book-spread) appears once the layout caps the reading column; toggling back is lossless.
  • Other states. Silent-prayer collapsibles («(тихо)» segments) init expanded/collapsed per revealSilentPrayers (Wave LF.1); a clergy-review chip overlay per block when isClergyModeUnlocked (Wave A.5); a soft, non-crashing error line on assemble failure («Не вдалося завантажити Літургію.»). Date navigation is wired through load(date) but reserved for a future date-picker — the reader defaults to today (clock()).

Navigation flow

The reader is reached by tapping the Літургія bottom-nav tab, which navigates to the "liturgy" route. LiturgyRoute obtains LiturgyViewModelV2 via Koin and renders LiturgyScreenV2. The route is deliberately not in MODAL_ROUTES — the bottom nav stays visible so the five-tab bar is the reader's escape hatch.

The TOC and the ♪ score sheet are in-screen sub-states owned by the ViewModel, not separate destinations — so the system Back button does not "close the TOC", it pops the whole tab. The TOC is dismissed with its close control / a section tap (jumpTo), and the ♪ sheet with a second ♪ tap (hideNotes). Date changes (future picker) call load(date) in-place; a live language-register change re-assembles while preserving the reader's position.
