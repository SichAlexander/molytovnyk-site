Purpose

The Psalter feature gives the user the complete book of the Psalms — all 20 kathismas — as a reading surface tuned for the app's audience of children (7+) and newcomers to the Ukrainian Greek Catholic tradition. The defining choice is verse-per-line rendering: loadKathismaContent calls formatPsalmText, which re-derives a line break at every numbered verse marker (and drops the marker itself, per the printed Молитовник convention), so each psalm verse reads on its own line rather than as a wall of prose.

Content is fully offline-first — psalms and closing prayers are read from the bundled psalter.json via the existing Room DAO, no cloud backend. The feature also hosts an optional group reading layer (parish "Spilne chytannia" cycle + weekly schedule) that surfaces only when a parish context exists; solo readers — every pilot user — bypass it and land directly on the kathisma list.

Functionality

  • 20 kathismas, 4 sections each. loadKathismaContent shapes every kathisma into exactly four PrayerCardModel sections: the three slavas (ПЕРША / ДРУГА / ТРЕТЯ СЛАВА) plus the closing prayer block (МОЛИТВА ПО КАТИЗМІ). The 3-slavas + 1-closing shape is pinned by the SECTIONS_PER_KATHISMA / SLAVAS_PER_KATHISMA constants in :core:domain and guarded at compile time.
  • Per-Slava navigation. The reader (KathismaReaderScreen) renders a 4-pip row (Слава 1 · Слава 2 · Слава 3 · Молитва); tapping a pip jumps the body to that section via onJumpToSection, resets the scroll, and each pip carries Role.Tab + selected semantics for TalkBack. Each slava closes with a styled doxology divider (the canonical SLAVA_DIVIDER, stripped from the card and re-rendered as a separator).
  • Kathisma list. KathismaListScreen lists all 20 kathismas ("Псалтир, 20 частин") with per-row psalm ranges and progress state (Pending / Current / Done) via KathismaListRow.
  • Reading schedule. PsalterScheduleRoute renders the parish group's ПН..ПТ weekly assignment table ("Розклад на тиждень"), reusing the home VM's state. A coordinator-only "Адмін" entry appears when PsalterAdminGateViewModel.canEdit is true (gated on the PSALTER_EDIT_INTENT capability).
  • List-detail (two-pane) layout. PsalterListDetailRoute routes on measured width: Compact (< 600dp) is the single-pane list (tap → standalone reader); Medium (600..999dp) shows a persistent list pane beside an in-place reader; Expanded-wide (>= 1000dp) adds a content-gated audio/score companion pane. The reader also offers a Сувій (scroll) / Книга (verse-per-line book-spread) toggle at Medium+, with the reading column capped to the 640dp measure.
  • Reader extras. A "Today's assignment" card, optional intention banner (suppressed for the implicit solo intention), and a clergy-mode unit_id chip + long-press correction-intent sheet (email / GitHub) when clergy mode is unlocked.

Navigation flow

The Psalter is a top-level destination, not a bottom-nav tab. None of its core route constants (Psalter, PsalterAll, PsalterSchedule, PsalterReader) are annotated @Modal, so the bottom nav stays visible throughout — the KSP-generated MODAL_ROUTES set excludes them. (PsalterAdminGrid, the coordinator schedule-grid editor, is the one @Modal route in the family.) It is reached two ways: from the Більше (More) tab (onOpenPsalterBrowser → navController.navigate(MolytovnykRoutes.Psalter)) and as a link from the Prayers list (Псалтир і канони group → onOpenPsalterAll → PsalterAll).

PsalterHomeRoute coordinates the entry: when there is no group context (no today-kathisma and no week rows — the solo case), it delegates straight to PsalterListDetailRoute so the kathisma list is the Psalter body with no detour; when a parish cycle exists, it renders the home cards (today-card, group-cycle polykandilon, "Усі кафизми →"). The schedule is reached from the group-cycle card's "Розклад на тиждень →" link. On Compact, tapping a kathisma navigates to the standalone reader route (psalter/reader/{kathismaNumber}); on Medium+ the list-detail route opens it in-place in the detail pane (no navigation). The reader's close ✕ pops back (hidden when it sits in a persistent detail pane, since the list pane is the navigation).

The capability gate is PsalterAdminGateViewModel — a standalone capability ViewModel that exposes a canEdit boolean flow, combining the user's CapabilityClaims with the current parish id against Capability.PSALTER_EDIT_INTENT. It coordinates whether the coordinator "Адмін" affordance on the schedule renders; the rules-side capability check remains the actual write gate.
