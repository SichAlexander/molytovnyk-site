Purpose

Спільнота is the app's parish / community surface. For ordinary members it answers "what is my parish doing this week?" — upcoming events (liturgies, festive services, prayer gatherings), Psalter prayer circles (Кола), and live communal Вервиця (rosary) sessions. For parish leaders it adds an admin layer — creating and editing events, viewing participant rosters, and managing who holds which role.

It is the only feature module backed by Firebase: events, circles, completions, and role grants live in Firestore, with FCM topic pushes and Firebase Auth custom claims behind the capability model. Crucially, the admin surface is capability-gated — entry points (the "+ Подія" pill, edit/cancel/create FABs) render only when the signed-in user's Auth custom claims grant the matching Capability for the current parish. Members never see admin chrome they cannot use.

Despite the Firebase backing, the module is offline-first by construction via the :core:data-cloud dormant-guard pattern — see Dependencies below. With no google-services.json, every cloud source short-circuits to empty and the surface still renders.

Functionality

  • Member home (CommunityHomeScreen / CommunityHomeViewModel) — the tab landing. Shows the parish header, "Цього тижня" upcoming-event list, the Psalter-circle "Коло" card, and (capability-permitting) the "+ Подія" create pill. The canCreateEvent flag is computed from parishRepo.currentParish combined with claimsFlow — the pill renders only when claims grant Capability.EVENT_EDIT_RECURRENCE for the current parish.
  • Event detail + subscribe (EventDetailScreen / EventDetailViewModel) — full event view with a "set intent" sheet (SetIntentSheet) and subscribe/notify affordance (FCM topic). Reached by tapping any card in the home list.
  • Prayer circles + history (CircleScreen / CircleViewModel, CircleHistoryScreen, plus CreateCircleScreen) — Psalter circle (Коло) detail with the Polykandilon ring of assigned kathismas, a calendar-dot history view, and a create-circle modal.
  • Live Вервиця (VervytsiaLiveScreen / VervytsiaLiveViewModel and VervytsiaOverviewScreen / VervytsiaOverviewViewModel) — a communal rosary session with a live halo (CommunalNimb) and completion tracking; the overview screen is the staging surface that fans out to the live session.
  • Eparchy events (EparchyEventsRoute) — the flat eparchy-wide events feed (events with no parish to gate against).
  • Admin hub (AdminHubScreen / AdminHubViewModel) — the per-event leader panel. buildUiState derives canEdit (EVENT_EDIT_OCCURRENCE), canCancel (EVENT_CANCEL_OCCURRENCE), and canCreate (EVENT_EDIT_RECURRENCE) from the user's CapabilityClaims for the event's parish; an occurrence-only editor never taps into a permission-denied create.
  • Create event — two flows: the full template-picker CreateEventRoute / CreateEventViewModel (template card + visibility chips; also reused in edit mode for EditEvent) and the lightweight SimpleEventCreateScreen / SimpleEventCreateViewModel (the "+ Створити подію" CTA, optionally pre-filled by name).
  • Participants roster (ParticipantsScreen / ParticipantsViewModel) — read-only per-event participant list reached from the admin hub.
  • Role hub (RoleHubScreen / RoleHubViewModel, with RosterScreen + AuditLogScreen + grant wizard) — the parish-wide "Ролі та доступ" surface: roster of people and their grants, a grant/revoke wizard, and an audit log. Backed by FirestoreRoleHubRepository in production (live roles/{uid} + auditLog docs via Firestore + Cloud Functions) and MockRoleHubRepository for JVM-pure tests / dormant builds.
  • Schedule matrix (CommunityAdminScreen + AdminScheduleMatrix / AdminScheduleTable) — the 20-cell weekly Psalter-coordinator assignment editor hosted under the community/psalter umbrella.
Capability-gating is the central invariant. All admin grants flow from Firebase Auth custom claims, parsed into CapabilityClaims (:core:domain permissions). claims.has(parishId, Capability.…) is the single gate predicate. A null claims value means "unknown" (gateway dormant or not yet refreshed) and is treated conservatively — no admin entry renders.

Exported as api so FirestoreRoleHubRepository can reach Firestore + Cloud Functions. Edge direction is one-way: :feature:community → :core:data-cloud; the cloud module never depends back on a feature.

Notable libraries: Compose BOM + Material3 + material-icons-extended (role/chrome glyphs — crown, church, shield, qr, key), Koin (ViewModel injection), kotlinx-coroutines, and Firebase (Firestore + Functions + Auth + FCM via :core:data-cloud).

Reverse-deps: :app registers every community route in MolytovnykNavGraph and resolves the ViewModels through Koin. :feature:home-v2 links into the tab (the Home community card and Psalter-circle card route into CircleRoute / the Community tab). No other feature depends on community.

Dormant-guard offline behavior. Because google-services.json is gitignored and stubbed in CI, the app must stay useful with no real Firebase. The guard: FirebaseApp.getApps(context) is empty until provisioned, so every cloud gateway short-circuits. FirebaseAuthGateway.signInIfNeeded / refreshClaims return null when dormant; FirestoreRoleHubRepository emits a single emptyList() and its grant/revoke become no-ops (surfacing "Firebase backend unavailable (dormant)"). Net effect: the community surface renders, no admin chrome appears (claims are null → no capability), and the app never crashes offline.

Navigation flow

Спільнота is the fourth bottom-nav tab, registered at the bare top-level route community (MolytovnykRoutes.Community) — it keeps the bottom nav. From the member home, tapping an event opens community/event/{eventId} (EventDetail); the Коло card opens community/circle/{parishId}/{circleId} (Circle); and a live-session tap lands first on the Вервиця overview, which fans out to community/live/{eventId} (VervytsiaLive). Every one of these detail/live destinations is annotated @Modal on its route constant (KSP-generated into MODAL_ROUTES), so it gets full-screen treatment and hides the bottom nav.

The admin path is capability-gated: the "+ Подія" pill on home and the admin entry points render only when CapabilityClaims grant the matching Capability for the parish. Admin destinations — AdminHub (community/admin/{eventId}), AdminParticipants (…/participants), CreateEvent (community/admin/create), SimpleEventCreate (community/create/simple), and RoleHub (admin/roles) — are all @Modal. Back behavior: after saving, create/edit flows popUpTo their origin (e.g. CreateEvent pops back to AdminHub; the in-event "open detail" pops AdminHub inclusive); back from the live session returns to the Вервиця overview (which is kept in the back stack via popUpTo(VervytsiaOverview)).
