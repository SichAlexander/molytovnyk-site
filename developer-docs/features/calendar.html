Purpose

Calendar is the V2 liturgical-calendar surface. It presents the church year so a child or newcomer can see, for any given day, what is celebrated, how it is fasted, and which vestment color is worn — derived deterministically from the same engine that drives the Divine Liturgy.

  • Movable + fixed cycles. Each cell runs CalendarService.getLiturgicalDayContext, which detects the movable cycle (Triodion / Pentecostarion / Octoechos period off the Butcher-algorithm Pascha) and resolves the fixed-date feast for the day.
  • Vestment color. VestmentColorResolver maps the day's LiturgicalDayContext (feast class, afterfeast/forefeast keys, movable-Sunday commemoration, season) to a VestmentColorUi (WHITE / GREEN / RED / PURPLE / GOLD) — total by design, with current-day feast taking precedence over a background afterfeast color.
  • Fast intensity. FastIntensityResolver derives a conservative, rule-defensible FastIntensityUi (NONE → DRY → BOILED → OIL → WINE → FISH → FULL_FAST) — Great Friday, Bright Week, the four multi-day fast seasons, weekly Wed/Fri abstinence, and explicit DailyInfo exemptions (Риба / Вино / Олива). Precise per-day katastasis is gated on Молитовник cross-source seeding (the /dyak gate).
  • Dual-calendar aware. CalendarMonthAssembler threads a calendarModeProvider (CalendarMode {GREGORIAN default, JULIAN}, read from UserPreferences.calendarMode) into every cell's resolve, so the grid re-reckons feasts on the user's old/new-calendar setting.

Functionality

  • Tabbed calendar (CalendarScreen). A persistent 4-tab pill row — CalendarTab.TODAY / WEEK / MONTH / FAST — over a single CalendarViewModel state. MonthTab renders a 6×7 Sunday-first grid assembled by CalendarMonthAssembler; WeekTab adds a compact "Ап. … · Єв. …" reading line; TodayTab focuses the current day; FastTab surfaces the fast view and a chronological AgendaListContent (feast rows merged with dated parish events) from YearAgenda.kt.
  • Per-day detail (DayDetailScreen / DayDetailViewModel). Full-screen reading for one day (ISO date nav arg via auto-wired SavedStateHandle): feast title, tone, vestment swatch, fast level (with real DailyInfo exemption flags), readings, and a primary CTA ("Молитися сьогодні" → prayer-of-day reader). Supports adding a personal event.
  • Full-text search (CalendarSearchScreen / CalendarSearchViewModel). A four-state overlay (empty-recents / typing / grouped results / no-results) over a debounced query pipeline — searches saints, feasts, and dates; a date-jump hero card; recent-search chips; and a no-results CTA that opens the simple-event-create form pre-filled with the typed query.
  • Tablet list-detail (CalendarDetailPaneRoute / CalendarDetailPaneViewModel). At ≥ 600dp width the screen switches to a ListDetailPaneScaffold (month grid in the list pane, day-detail inline in the detail pane keyed on the selected date); compact (< 600dp) flow is byte-identical to the phone baseline. Layout routes on measured dp width, never on orientation.
  • Admin create-schedule (CreateScheduleScreen / CreateScheduleViewModel). Capability-gated liturgy-schedule editor for a day (add/remove service rows, time/name/location, highlight, publish). Reached only when the Day-Detail capability gate (state.canEditSchedule, off event.edit_recurrence) is true; a successful publish auto-pops back to Day Detail.

Navigation flow

Calendar is not a bottom-nav destination — it is entered from Home's upcoming-events card (and the dedicated Upcoming-Events list). The grid route (calendar) is top-level and keeps the bottom nav; the day-detail, search, and admin-schedule routes are @Modal and take the full canvas. From the grid, tapping a day navigates to calendar/day/{date}; the header magnifier opens calendar/search; an admin affordance on the day opens calendar/schedule/{date}. Back is always popBackStack() (search and day-detail land back on the calendar; a successful schedule publish auto-pops to day-detail). On a tablet (≥ 600dp) a day tap in the grid does not navigate — it selects, and the detail renders inline via CalendarDetailPaneRoute.
